# Expert Decision Replay Platform — Security Architecture & Controls

This document details the active security controls, cryptographic measures, authorization policies, and compliance safeguards implemented within the Expert Decision Replay Platform.

---

## 1. Implemented Security Controls

### 1.1 Password Hashing & Credential Storage
- **Algorithm**: `bcrypt` via Passlib / Python `bcrypt` library.
- **Cost Factor / Rounds**: 12 rounds of key stretching.
- **Salting**: Cryptographically random unique salt generated per password automatically.
- **Zero-Plaintext Invariant**: Plaintext passwords are never stored in memory structures or persisted to disk. All user response schemas (`UserResponse`) explicitly exclude password hash fields.

### 1.2 Stateless JWT Token Authentication
- **Signing Algorithm**: HMAC-SHA256 (`HS256`).
- **Token Claims**: `sub` (user_id), `email`, `role`, `exp` (expiration), `iat` (issued at).
- **Expiration Policy**: Enforced by `ACCESS_TOKEN_EXPIRE_MINUTES` (defaults to 24 hours).
- **Validation**: Every authenticated request passes through the `get_current_user` FastAPI dependency:
  - Validates cryptographic signature using `SECRET_KEY`.
  - Verifies token expiration timestamp.
  - Checks if user account is marked `is_active == True`.

### 1.3 Role-Based Access Control (RBAC)
Role authorization is strictly enforced at the route level via the `require_roles` dependency factory:

- **Employee**: Scoped to self-created drafts, assigned team spaces, public/approved decision viewing, and discussions.
- **Reviewer**: Elevated access to pending review queues and single-step approval actions.
- **Manager**: Elevated access to team leadership workflows, team join approvals, multi-step approvals, and organizational analytics.
- **Administrator**: Global administrative authority: user status toggling, role reassignments, category governance, and audit inspection.

Attempts to access routes without necessary role claims produce `HTTP 403 Forbidden`.

### 1.4 Object-Level Authorization (Ownership Enforcement)
Beyond role checks, individual business services validate entity ownership:
- **Decision Modification**: Only the author (in `Draft` status) or an Administrator may modify or delete a decision.
- **Discussion Management**: Only the comment author or an Administrator may edit or delete a discussion comment/reply.
- **Document Management**: Only the uploader, decision owner, or an Administrator may delete an attached document.
- **Team Management**: Only the designated Team Lead or an Administrator may approve join requests or remove team members.

### 1.5 File Upload Security & Path Traversal Prevention
Document attachment endpoints enforce strict upload constraints:
- **File Size Cap**: Requests exceeding `MAX_UPLOAD_SIZE_BYTES` (10 MB) are rejected with `HTTP 413 Payload Too Large`.
- **Extension Whitelisting**: Restricted to `.pdf`, `.doc`, `.docx`, `.xls`, `.xlsx`, `.ppt`, `.pptx`, `.txt`, `.csv`, `.png`, `.jpg`, `.jpeg`. Executables and dangerous script formats (`.exe`, `.sh`, `.bat`, `.js`, `.py`) are rejected.
- **UUID Filename Obfuscation**: Files are saved with UUID-derived filenames on disk (`{uuid}_{sanitized_name}`) to prevent collisions and null-byte injection.
- **Path Traversal Protection**: Directory traversal sequences (`../`, `..\\`) are stripped using `os.path.basename` and resolved against absolute base paths.

### 1.6 Audit Logging & Immutability
- **Automatic Audit Records**: High-impact domain operations (`USER_LOGIN`, `DECISION_CREATED`, `DECISION_SUBMITTED`, `DECISION_APPROVED`, `DECISION_REJECTED`, `DECISION_UPDATED`, `DOCUMENT_UPLOADED`, `ROLE_UPDATED`, `STATUS_UPDATED`) generate audit logs.
- **State Capture**: Records include `user_id`, `action`, `entity_type`, `entity_id`, `old_values` (JSON snapshot), and `new_values` (JSON snapshot).
- **Append-Only Immutability**: The `audit_logs` table has no `UPDATE` or `DELETE` endpoints exposed in the API router. Audit data can only be inserted or queried.

### 1.7 Input Validation & Privacy Scrubbing
- **Strict Schemas**: Powered by **Pydantic v2**. Enforces typing, string bounds, and regex constraints (e.g. valid RFC email syntax, minimum password length).
- **Privacy Scrubbing**: Audit payloads sanitize password fields, ensuring secret keys or password text never appear in `old_values` or `new_values` JSON structures.

### 1.8 Database Connection Security
- Connection pooling with `pool_pre_ping=True` ensures stale or dropped connections are safely recycled.
- Parameterized SQL queries generated by SQLAlchemy ORM eliminate SQL injection vulnerabilities.

### 1.9 Cross-Origin Resource Sharing (CORS) Controls
CORS middleware explicitly restricts origins to trusted development and deployment targets:
- `http://localhost:5173`, `http://127.0.0.1:5173` (Vite dev)
- `http://localhost:3000`, `http://127.0.0.1:3000` (Alternative client)
- `http://localhost`, `http://127.0.0.1`, `http://localhost:80`, `http://127.0.0.1:80` (Docker production)
Wildcard (`*`) origin access with credentials is prohibited.

## 2. Docker Security Architecture

The containerized setup implements container isolation best practices:
- **Non-Root / Slim Base Images**: Uses official `python:3.11-slim` and `nginx:alpine` to minimize vulnerability surface area.
- **Isolated Internal Network**: Database is attached to internal bridge network `expert_decision_network` and is not exposed to external public interfaces.
- **No Secrets in Images**: `.dockerignore` excludes `.env`, `venv/`, and sensitive files from being baked into image layers.
- **Volume Isolation**: Databases and uploads persist in Docker named volumes outside container root filesystems.

## 3. Future Security Recommendations

While the platform implements robust enterprise controls, the following enhancements are recommended for enterprise production deployment:

1. **HTTPS / TLS Termination**: Place an external reverse proxy (e.g. AWS ALB, Cloudflare, Traefik) terminating TLS 1.3 in front of the application.
2. **Refresh Token Rotation**: Implement short-lived access tokens (15 minutes) with rotating refresh tokens stored in HTTP-only, Secure, SameSite cookies.
3. **Rate Limiting**: Integrate rate-limiting middleware (e.g., Redis-backed `slowapi`) to mitigate brute-force attempts on `/auth/login`.
4. **Virus / Antivirus Scanning**: Integrate ClamAV scanning for uploaded documents prior to disk commitment.
5. **Secrets Vault**: Transition environment variables to HashiCorp Vault or AWS Secrets Manager in cloud environments.
